# البنية المعتمدة وخطة بناء تطبيق SUPER TRADING BOT

**حالة الوثيقة:** معتمدة كبنية تنفيذية أولية  
**الإصدار المرجعي:** 1.2.0  
**التاريخ:** 2026-11-16  
**المنصات:** Android (PWA + APK) وWindows 11 (EXE + Browser)

## 1. القرار المعماري

يعتمد المنتج واجهة أمامية مشتركة واحدة، مع أغلفة تشغيل أصلية حسب المنصة، وخدمات تداول منفصلة عن واجهة المستخدم:

- **PWA:** نسخة الويب التقدمية الحالية، وتعمل من متصفح حديث عبر HTTPS، ويمكن تثبيتها على شاشة Android.
- **Android APK:** تغليف نفس واجهة الويب باستخدام Capacitor، مع إضافات أصلية محدودة للإشعارات والتخزين الآمن. لا يحتوي APK على مفاتيح وسيط أو أسرار خادم.
- **Windows Browser:** لوحة الويب نفسها، تفتح من المتصفح عبر HTTPS أو من عنوان محلي آمن في وضع التطوير.
- **Windows EXE:** غلاف سطح مكتب باستخدام Tauri 2 لعرض اللوحة والتحكم في حالة الوكيل المحلي. لا يعيد كتابة منطق التداول داخل الواجهة.
- **Windows MT5 Agent:** عملية Python مستقلة تُعبأ لويندوز، وتتصل بمحطة MT5 المثبتة محليًا. يظل حساب الوسيط مسجلًا داخل MT5، ولا يطلب التطبيق كلمة مرور التداول.
- **Backend:** FastAPI + PostgreSQL في بيئة الإنتاج، مع جلسات وصلاحيات وتراخيص وإدارة مخاطر وسجل تدقيق. في التجربة الخاصة يمكن تشغيله على Windows وربط الهاتف عبر VPN فقط؛ أما المنتج متعدد العملاء فيحتاج استضافة HTTPS موثوقة.

## 2. حدود الثقة والاتصال

```text
Android PWA / APK                 Windows Browser / Tauri EXE
        |                                      |
        +----------- HTTPS + Auth -------------+
                           |
                    FastAPI Backend
                           |
                 PostgreSQL + Audit Log
                           |
                 قناة Agent موثقة ومحدودة
                           |
                Windows MT5 Agent (محلي)
                           |
                 MetaTrader 5 Terminal
                           |
                       الوسيط
```

- لا يتصل Android مباشرة بمحطة MT5 ولا يرسل أوامر إلى الوسيط.
- الوكيل يبدأ الاتصال الصادر إلى الخادم؛ لا نفتح منفذ MT5 أو منفذ الوكيل للعامة.
- في التشغيل الخاص، يقتصر الوصول من الهاتف إلى Windows على VPN مثل WireGuard/Tailscale أو HTTPS عبر بوابة موثوقة؛ لا يُفتح منفذ الراوتر مباشرة.
- تُفصل بيانات كل عميل وحساب تداول عن بقية العملاء على مستوى قاعدة البيانات والصلاحيات.
- الأخبار وإشارات البوتات الخارجية بيانات غير موثوقة للتحليل فقط، ولا تتحول إلى أوامر تنفيذ.

## 4. مكونات كل تطبيق

### Android PWA وAPK

- نفس واجهة `frontend/` دون نسخ منطق التداول.
- جلسة مستخدم آمنة، مع دعم تدوير الجلسات وإبطالها.
- تخزين رموز الجلسة في Android Keystore عبر إضافة Capacitor موثوقة عند بناء APK؛ لا تحفظ الأسرار في LocalStorage.
- إشعارات Push اختيارية بعد إعداد خدمة الإشعارات وموافقة المستخدم.
- لا تُخزن بيانات الحساب أو الصفقات الحساسة للعمل دون اتصال. يسمح Offline فقط بصفحات ثابتة غير حساسة، مع بيان وقت آخر مزامنة.
- زر إيقاف التداول يرسل أمر إيقاف موثقًا للخادم، ويعرض حالة تأكيد وصول الأمر للوكيل؛ لا يدّعي نجاح الإيقاف قبل تأكيده.

### Windows EXE وBrowser

- غلاف Tauri 2 خفيف يستخدم WebView2 على Windows 11.
- شاشة حالة للـ Backend والوكيل وMT5، مع سجلات تشغيل واضحة.
- أوامر تشغيل/إيقاف الوكيل لا تتجاوز موافقات التداول وبوابات المخاطر.
- يُعبأ MT5 Agent منفصلًا باستخدام PyInstaller بعد اختبار الاعتماديات، ويعمل كمهمة/خدمة Windows محدودة الصلاحيات.
- يثبت EXE عبر مثبت Windows موقّع (مثل WiX أو Inno Setup بعد اعتماد مسار البناء). لا تُحفظ مفاتيح توقيع التطبيق داخل المستودع.
- يمكن استخدام لوحة المتصفح دون تثبيت غلاف EXE، لكن التداول يتطلب وجود الوكيل على Windows واتصال MT5.

## 5. بوابات سلامة التداول

1. الوضع الافتراضي عند التثبيت هو **Analysis / Sync فقط**؛ لا إرسال أوامر.
2. DEMO يتطلب حساب MT5 تجريبيًا، وموافقة صريحة، وفحص `order_check` قبل `order_send`.
3. REAL مغلق افتراضيًا على الخادم والوكيل معًا. لا يُفتح إلا بعد موافقة مستقلة محفوظة، وتفعيل المالك، وتأكيد محلي، واجتياز مراجعة قانونية وأمنية واختبارات DEMO.
4. كل أمر يمر عبر Risk Manager مستقل؛ لا يستطيع العميل أو المساعد الذكي أو مصدر الأخبار تجاوز قراراته.
5. عند غياب بيانات الحساب أو الأسعار أو الهامش أو فشل التحقق، يكون القرار **رفض التنفيذ**.
6. إيقاف التداول الطارئ يمنع فتح صفقات جديدة ويوقف الوكيل؛ إغلاق المراكز القائمة إجراء منفصل يحتاج تأكيدًا صريحًا وسياسة محددة.
7. تسجل كل موافقة وتغيير إعداد وقرار رفض وتنفيذ في سجل تدقيق غير قابل للتعديل من واجهة العميل.
8. حدود البداية المحافظة الموجودة في الإصدار 1.2.0 (0.25% للصفقة، 1% خسارة يومية، 1% مخاطر مفتوحة، 3 مراكز، ومركز واحد لكل رمز) تبقى حدودًا أولية قابلة للمراجعة والاختبار، وليست ضمانًا ضد الخسارة.
9. هدف دقة هندسية مثل 0.01% يُقاس بمؤشرات وأخطاء محددة؛ لا يُسوّق كضمان أو كحد أقصى للخسائر.

## 6. مراحل التنفيذ ومعايير القبول

### المرحلة A — تدقيق الأساس الحالي

- مراجعة مسارات المصادقة والجلسات وعزل العملاء والمالك.
- فحص migrations والنسخ الاحتياطية وعدم استخدام downgrade هدّام على الإنتاج.
- اختبار API والواجهة والوكيل من بيئة نظيفة.
- إصلاح أي ثغرة حرجة قبل إضافة أغلفة التطبيقات.

**قبول المرحلة:** لا ثغرات حرجة/عالية غير معالجة، وكل اختبارات الأساس تمر، وREAL لا يزال مغلقًا.

### المرحلة B — إكمال PWA

- اختبار التثبيت على Android وWindows.
- مراجعة Service Worker وسياسة التخزين المؤقت لمنع تخزين ردود API الخاصة.
- اختبار تسجيل الخروج وإبطال الجلسة وانقطاع الشبكة.

**قبول المرحلة:** تثبيت وتشغيل وتحديث آمن، وعدم ظهور بيانات حساسة بعد تسجيل الخروج أو من Cache.

### المرحلة C — Android APK

- إنشاء مشروع Capacitor وربطه بالواجهة المشتركة.
- إضافة Secure Storage وPush Notifications عند الحاجة فقط.
- بناء Debug APK للاختبار أولًا، ثم Release APK موقّع بمفتاح يملكه صاحب المنتج.

**قبول المرحلة:** تثبيت نظيف، دخول وخروج، تخزين آمن، عدم وجود أسرار داخل APK، واختبارات الشبكة والإشعارات.

### المرحلة D — Windows Agent Runtime

- تجهيز بيئة Python مدعومة على Windows 11.
- بناء الوكيل كحزمة مستقلة، وإدارة إعداداته عبر مخزن أسرار Windows أو ملف محلي محمي.
- إضافة مراقبة الصحة وإعادة الاتصال وتسجيل الأخطاء دون تسجيل الرموز السرية.

**قبول المرحلة:** الوكيل يعمل بعد إعادة تشغيل Windows، ويستعيد الاتصال بأمان، ولا يرسل أمرًا في وضع التحليل.

### المرحلة E — Windows EXE

- إنشاء Tauri 2 shell ولوحة الحالة والتحكم.
- ربط أوامر التحكم بواجهات مصادق عليها وبالوكيل المحلي فقط.
- بناء مثبت تجريبي، ثم اختبار التحديث والإزالة والرجوع إلى إصدار سابق.

**قبول المرحلة:** يعمل EXE على Windows 11 نظيف، ولا يفتح صلاحيات أو منافذ غير مطلوبة، ويمكن إيقاف الوكيل دون حذف بياناته.

### المرحلة F — اختبارات DEMO ثم إطلاق محدود

- اختبار على حساب Demo للوسيط المختار وعلى رموز وفترات مختلفة.
- اختبار الانقطاع وإعادة الاتصال والانزلاق والسبريد واتساع الفجوات والرفض الجزئي والتنفيذ الجزئي.
- مراجعة رسوم الأداء على المراكز المغلقة، بما في ذلك السواب والعمولة والتجميع حسب position_id.
- مراجعة قانونية وتنظيمية حسب بلد التشغيل قبل أي خدمة مدفوعة أو عمولة أداء.

**قبول المرحلة:** تقرير نتائج قابل لإعادة الإنتاج، وعدم وجود تجاوز لمخاطر الحساب في اختبارات الفشل، وموافقة مكتوبة قبل فتح أي حساب حقيقي.

## 7. متطلبات البناء والتوقيع

- Node.js LTS لبناء الواجهة وCapacitor وTauri.
- Android Studio + Android SDK لبناء APK.
- Rust toolchain + Microsoft Visual Studio Build Tools + WebView2 لتجميع Tauri على Windows.
- Python 3.11+ وMetaTrader 5 على Windows لبناء واختبار MT5 Agent.
- مفاتيح توقيع Android وWindows تحفظ خارج Git وفي مكان آمن لدى المالك.
- لا يمكن إنتاج APK/EXE نهائي موقّع موثوق دون إعداد بيئة البناء ومفاتيح التوقيع المملوكة لصاحب التطبيق.

## 8. ما لا تدعيه هذه المرحلة

هذه الوثيقة تضيف قرارًا معماريًا وخطة بناء إلى أساس 1.2.0. لا تعني أن APK أو EXE قد بُنيا أو وُقّعا، ولا أن وسيطًا حقيقيًا قد اختُبر. لا يوجد اتصال تداول حقيقي من معاينة الهاتف الحالية. لا تُحذف النسخة القديمة أو قواعد البيانات أثناء الترقية؛ تُحفظ نسخة احتياطية ويُنفذ ترحيل قابل للرجوع قبل اعتماد أي إصدار جديد.
